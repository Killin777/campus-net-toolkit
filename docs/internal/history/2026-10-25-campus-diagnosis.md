## 一、诊断结论

排查时网络**本身是通的**（百度/腾讯/知网/学校官网全部 200，网关 30 包 0 丢包），
问题集中在三处：

| # | 现象 | 证据 | 性质 |
|---|---|---|---|
| 1 | **链路被无线控制器反复踢下线** | WLAN 事件日志：18:52–18:58 每 **5~20 秒**一次"安全停止/安全成功"；21:07–21:18 每 **60~110 秒**一次。每次都是同一秒内 `断开→重建` | AP 侧 Deauth / 负载均衡，**客户端参数改不动** |
| 2 | **信号处于覆盖边缘** | RSSI 稳定在 **−67 ~ −72 dBm**，信号 46%~80% 来回跳；BSSID 在 `<BSSID-A>`(5G ch157) / `<BSSID-B>`(5G ch44) / `<BSSID-C>`(2.4G ch11) 之间漂移 | 位置离 AP 远，弱信号会触发控制器的"弱信号下线"阈值 |
| 3 | **国际站点直连全部超时** | GitHub / Google / YouTube / Steam / <IP> / <IP> 全部 TCP 超时；国内站点 200 | 校园网出口策略，**不是故障**，走代理即可 |

其他发现：

- **网关丢包 0%、MTU 1500 无黑洞**，链路层健康。
- **IPv6 未下发**：WLAN 只有 `fe80::` 链路本地地址，无全局 IPv6（教育网 IPv6 资源用不了）。
- **校园网关存在 TLS 中间人**：Tailscale 连 `derp2f.tailscale.com` 时收到自签证书
  `CN=demotest.doctorcom.com, O=Doctorcom LTD.`（Dr.COM 城市热点设备），
  Tailscale 因此判定 "likely intercepted connection"。部分应用的证书校验会因此失败。
- **Clash Verge 开了服务模式**：内核 `verge-mihomo.exe` 是 `clash-verge-service`(SYSTEM) 的子进程，
  普通权限杀不掉 —— 这是"关了 Clash 但代理还在/网还断"的隐藏原因。
- **Radmin VPN 接口跃点 = 1**（最低）。WLAN 掉线且无其他链路时，默认路由会落到
  `<IP>`，流量钻进 VPN 隧道，表现为"断网很久"而不是"立刻失败"。
- **有线口是通的**：`以太网` 已连接 `<IP>/24`，网关 2ms，metric 35 已优于 WLAN 的 60
  —— Windows 会自动优先走有线。但协商速率从 100Mbps **掉到 10Mbps**，疑似网线/端口接触不良。

## 二、已做的修改

### 1. 无线网卡

| 参数 | 原值 | 现值 | 作用 |
|---|---|---|---|
| `RoamAggressiveness` 漫游主动性 | 0 = **1.最低值** | 0（曾误设为 1，已改回） | 最不激进，减少主动漫游与频段漂移 |

| `MIMOPowerSaveMode` | 3（无 SMPS） | 3 | 保持关闭 MIMO 节能 |
| 电源计划·无线适配器节能 | 0（最高性能） | 0 | 保持 |

原值备份：`wifi-backup-20261025-212012.json`

> **重要更正**：Intel 驱动的这些值是 0 基编号，`RoamAggressiveness=0` 才是显示里的
> 「1. 最低值」，`=1` 是「2. 中低」。最初把 0 当成"非法值"改成 1 是错的，
> 反而更激进，已改回 0。`RoamingPreferredBandType=2` 则是「3. 首选 5GHz」，
> 不是先前误写的 2.4GHz。
>
> 这两项在**下次无线重连后生效**（为避免打断正在跑的游戏，没有强制重启网卡）。
>
> 另：`PacketCoalescing` / `DeviceSleepOnDisconnect` 在该驱动上不在 WMI 可写列表里，
> 但注册表值本来就是 0，无需处理。

## 四、Clash 开关工具（为"经常开关"设计）

桌面 `校园网工具` 文件夹（`<INSTALL_DIR>`）：

| 快捷方式 | 作用 |
|---|---|
| ① Clash 开 | 启动 Clash Verge，**等内核真正监听 7897 之后**才设置系统代理 |
| ② Clash 关 | 先停内核（服务模式下自动提权），**再**清除系统代理 |
| ③ Clash 切换 | 二合一，按当前状态反向切换 |
| ④ Clash 状态 | 看端口 / 系统代理 / 是否有残留 |
| ⑤ 网络急救 | 清代理残留 + 刷新 DNS + 探测网关，断网时先点这个 |
| （高级）修复 WiFi 掉线 | 重新应用网卡参数并重启网卡（自动提权，断网约 10 秒） |

### 为什么需要脚本

手动点 GUI 时，如果 Clash 被强杀/崩溃，系统代理会残留指向 `127.0.0.1:7897` 这个死端口，
浏览器就一直卡在等超时 —— 表现就是"校园网突然全网打不开"。

**本机还叠加了服务模式**：内核是 `clash-verge-service`(SYSTEM) 的子进程，
普通权限 `Stop-Process` 杀不掉，所以以前"关掉 Clash"可能只是关了界面、内核还在跑。
脚本会检测这种情况并**自动提权停内核**（本机 UAC 为"提权不提示"，无弹窗）。

脚本保证：**开 = 内核就绪后才设代理，关 = 内核先死代理后清**，不会出现半死不活的状态。

### 命令行用法

```powershell
<INSTALL_DIR>\legacy\ClashCtl.ps1 on       # 开
<INSTALL_DIR>\legacy\ClashCtl.ps1 off      # 关
<INSTALL_DIR>\legacy\ClashCtl.ps1 toggle   # 切换
<INSTALL_DIR>\legacy\ClashCtl.ps1 status   # 状态
<INSTALL_DIR>\legacy\ClashCtl.ps1 fix      # 急救
```

代理已配置的绕过列表：`<local>;localhost;127.*;10.*;172.16.*~172.31.*;192.168.*;*.example.edu.cn`
（校内地址直连，不走代理，避免访问图书馆/教务时反而变慢）

## 六、后续建议（按性价比排序）

1. **优先用有线。** 有线已连上且 metric 更优，Windows 会自动优先。
   WiFi 在这位置是 −70dBm 边缘覆盖，再怎么调也是治标。
2. **若仍频繁掉线**：把 `wlan-monitor.log` 的时间点和 `Get-WinEvent` 的 WLAN 日志一起
   报给网络中心 —— 大概率是 AP 负载均衡/弱信号踢人，客户端救不了。
3. **IPv6 用不了**：需在校园网自助服务里开通 IPv6，或换支持 IPv6 的接入方式。
4. **Radmin VPN 不用时禁用网卡**，避免 WLAN 掉线时流量被吞进 VPN 隧道。
5. **Tailscale** 因 Dr.COM 中间人导致 DERP 连不上，可用 `--login-server` 自建节点或走代理。
6. **别开 Clash Verge 的"代理守卫"**（当前 `enable_proxy_guard: false` 是对的）：
   它只会在内核已死时反复把代理设置回去，反而让断网更顽固。

### 实测瓶颈

| 指标 | 结果 | 判读 |

| ping 手机网关（不出 4G） | 平均 23.9ms，**P50 7ms / P95 63ms / 最大 641ms**，60 包里 10 个 >30ms | 瓶颈在**这段 Wi-Fi / 手机热点**，不在 4G 上行，也不在电脑 |

| 项目 | 改动 | 效果 |
|---|---|---|
| WLAN DNS | 静态 <IP> → **DHCP 自动（网关 10ms）** | 解析延迟降 3~30 倍 |
| Radmin VPN 跃点 | 1 → **9000** | 不再抢占默认路由，避免断网时流量被吞进隧道 |
| 传递优化 | 默认 → **仅 LAN（DODownloadMode=1）** | 禁止 Windows 更新对公网做 P2P 上传 |
| 漫游主动性 | 1（中低）→ **0（最低）** | 减少主动漫游与扫描 |
| 2.4GHz 带宽 | 自动（40MHz）→ **20MHz** | 拥挤频段减少重传 |

脚本：`legacy\Optimize-Network.ps1`（需管理员，可重复运行）、`legacy\Fix-Roaming-Param.ps1`
备份：`network-backup-20261025-231742.json`

### 结论

**电脑侧已经查不出明显瓶颈**。剩下的卡顿来自手机热点这段无线链路：
15% 的包延迟超过 30ms、偶发 640ms 尖峰，这是 Android 热点的调度特性，客户端改不了。

要真正"怎么用都不卡"，按效果排序：

1. **手机热点切 5GHz**（设置里把"AP 频段"改成 5GHz）—— 2.4GHz 干扰大、40MHz 更甚，
   换 5GHz 通常能把抖动砍掉一大半。
2. **用有线**（宿舍/工位有墙口的话）—— 一劳永逸。
3. **别同时开重流量**：玩游戏时不要同时挂着远程桌面推流、网盘同步、视频。
4. **Clash 只在需要外网时开**，平时关掉可少一层本地转发和额外连接。
5. 若换回校园网 `<SSID>`，注意它 −70dBm 边缘覆盖 + 控制器踢人，不如有线。

## 十二、v1.2：三种模式 + 代理无关化（2026-10-26）

### 三种模式

顶部一排按钮，点一下就切换，当前模式会高亮，状态栏同步显示。

| 模式 | 做什么 | 注意 |
|---|---|---|
| **① 国内直连** | 关系统代理 → 清 PAC → DNS 回自动 → 刷缓存；检查 TUN 劫持、VPN 抢路由、环境变量残留 | 国外网站会打不开，这是预期 |
| **② 科学上网** | 自动找代理端口 → 5 层验证 → 通过才开系统代理 → 验证出口 | 验证不过会**拒绝开启**，不会瞎设 |
| **③ 游戏优化** | 停 Windows 更新/传递优化 → 高性能电源 → 关网卡省电 → 关代理（国服走直连）→ 检查路由与丢包 | 不碰注册表"TCP 神油" |
| **还原模式** | 从 `mode-state.json` 恢复服务和电源方案 | 替代了原来的「低延迟模式」 |

游戏模式在结尾会明说真正影响延迟的是什么（物理链路 > 信号强度 > 同网段占用 > 后台更新），
不制造"点了就变快"的错觉。

### 代理不再绑定具体客户端

新增 `ProxyCtl.ps1`，只认"当前生效的出口"，不认品牌：

- **探测**：读系统代理注册表 → 扫常见端口（7897/7890/10809/7891/10808/2080/20171/1080）→ 每个都做协议识别
- **协议识别**：真的发 `CONNECT` 或 SOCKS5 握手，区分 HTTP / SOCKS5 / 认证代理 / 根本不是代理
- **5 层验证**：端口活着 → 协议对得上 → 经代理访问国内 204 → 经代理访问 Google → 系统代理是否指向它
- **开代理前看 `Capable`（前 4 层），不看 `Ok`（含第 5 层）** —— 否则"没开代理"会导致永远开不了

实测结论示例：

```
  √ 端口 7897 监听                PID 49932 verge-mihomo
  √ 协议识别                      HTTP 代理（CONNECT 成功）
  √ 经代理访问国内 204            204 / 66ms
  √ 经代理访问 Google             200 / 1389ms
  √ 系统代理一致性                指向 127.0.0.1:7897
结论：配置正确，代理可用。
```

端口不通时会自动扫一圈，找到可用端口并保存。

### 调研中发现的、容易忽略的四个坑

已写进 `ProxyCtl.ps1 envcheck`：

1. **WinHTTP 是独立配置**。系统代理只覆盖 WinINET（浏览器），用 WinHTTP 的程序不看注册表。
   这是"浏览器能上网、命令行工具不行"的常见原因。
2. **UWP 应用默认不能连 127.0.0.1**（WFP 隔离）。商店应用不走本地代理是系统限制，
   需要 `CheckNetIsolation LoopbackExempt -a -n=<包族名>` 放行。
3. **`localhost` 会解析到 `::1`**，而很多客户端只监听 `127.0.0.1` → 连不上。配置里一律用 `127.0.0.1`。
4. **`*_PROXY` 环境变量优先级高于系统代理**，残留会让 git/npm/pip 走错端口。
   但 `no_proxy` 只是绕过清单，无害——早期版本把它误报成残留，已修。
