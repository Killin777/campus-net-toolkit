## 1. 目标与范围

把现有 demo 整理成后续能看懂、能修改、能验证、能重新构建的 Windows 工具，保留双击 EXE 一键使用。

本轮只围绕以下三件事开展：

1. **工作区整理**：明确源码、构建工具、配置、运行数据、历史材料和文档的位置，提供维护入口。
2. **EXE 权限绑定**：首次询问是否始终以管理员权限启动，记住当前 Windows 用户的选择，并提供修改入口。
3. **功能合理性检查**：依据校园网本地诊断与可还原维护的定位，核对功能、权限、确认提示、备份与还原是否一致。

本轮不增加新的校园网功能，不更换界面技术栈，不修改校园网认证行为。功能修复仅限查实且影响上述目标的缺陷；较大的功能调整先记录处理建议。

## 3. 工作区整理方案

| 位置 | 职责 | 整理动作 |

## 4. EXE 封装与管理员权限方案

### 4.1 权限行为

首次双击 EXE，询问：**“是否以后默认以管理员权限启动？”**

| 用户选择 | 当次与后续行为 |
|---|---|
| 是 | 保存“默认管理员启动”；当次请求管理员授权，后续启动继续遵循 Windows 的 UAC 规则 |
| 否 | 保存“普通权限启动”；允许查看状态和只读检查，修改系统设置时明确提示需要管理员 |
| 取消 | 不保存新选择，本次退出，下次继续询问 |

- 偏好按当前 Windows 用户保存于数据目录下的 `runtime/launcher.json`。
- 设置窗口提供“启动权限”入口，修改后于下次启动生效。
- 普通权限窗口提供一次性以管理员重新打开的入口。
- UAC 被取消时明确反馈，当前运行窗口保持可用，或结束尚未开始的启动流程。
- “记住选择”表示保存启动偏好，不表示永久获得系统管理员授权。

### 4.2 封装行为

在保留 PowerShell 5.1 与 WinForms 的基础上，把主程序、所需模块及默认示例作为 EXE 内置资源。运行时释放并校验程序文件，配置和备份独立于版本缓存。

| 项目 | 要求 |
|---|---|
| 用户入口 | 仍为根目录 `网络优化器.exe`，双击可用 |
| 源码入口 | 保留 `.cmd` 兼容入口及源码调试方式，说明其权限行为 |
| EXE 独立性 | 将 EXE 单独复制到中文、空格目录，能释放资源并运行 |
| 数据位置 | EXE 使用当前用户本地数据目录；源码运行使用项目数据目录，均将生成内容置于 `runtime` |
| 发布白名单 | 只包含必要源码、配置示例、版本和使用/维护说明 |
| 不打包的内容 | 真实配置、运行日志、历史备份、快捷方式、临时检查目录、旧脚本 |
| 构建复现 | `tools/Build.ps1` 可从源码重新生成 EXE，并给出版本、文件清单与 SHA-256 |
| 错误反馈 | 缺资源、校验失败、主程序异常退出都有可见提示或可定位日志 |

## 5. 功能合理性检查方法

逐项检查现有功能，给出“保留、修复、调整文案、后续建议”之一，并写明证据。默认采用读取代码、隔离状态目录与替代系统调用验证，不实际切换这台电脑的 DNS、停止服务或重启网卡。

| 检查对象 | 核对重点 |
|---|---|
| 校园网检测与登录页 | 检测结论是否有证据；是否仅打开登录页；不保存凭据、不代替认证 |
| 一键体检、延迟与时间线 | 超时、ICMP 被屏蔽、无线信息不可用时，是否给出准确且不过度推断的提示 |
| 代理状态与控制 | 是否检测系统实际代理地址；是否把“配置端口未监听”误判为故障；查看状态是否意外改设置 |
| DNS 优选 | 失败响应是否被计时；是否考虑校园内网依赖学校 DNS；是否先备份和明确确认 |
| 批量调优与游戏模式 | 所改设置是否符合定位；权限和确认是否充分；有无“必然降低延迟”等无法证明的承诺 |
| 备份与还原 | 是否保存原始值和自动/静态状态；失败后是否保留记录；能否再次执行还原 |
| 网络急救 | 是否会误重启网卡；是否绑定实际网卡；是否对可能断网的步骤给出确认 |
| 设置与报告 | 配置是否写入正确目录；保存和失败提示是否真实；导出的本机信息是否有明确用途 |

已查实、需要优先核对的缺陷：

1. DNS 查询失败后仍记录用时，可能把快速失败选为最快。
2. 根据配置端口自动关闭系统代理，可能误伤其他有效代理。
3. 部分还原失败后清空状态，不满足可重试还原的要求。
4. DNS 备份未记录自动/静态来源，恢复时可能把自动地址固定。
5. 子进程参数缺少统一转义，中文与空格路径需要实测。

- [ ] 完成功能清单与上述证据核对。
- [ ] 对与封装、权限和数据安全直接相关的查实缺陷做最小修复。
- [ ] 对较大行为调整保留检查结论和建议，明确是否影响交付。
- [ ] 同步修正说明文案，使界面承诺与实际代码一致。

验收：每个修改系统状态的功能都有清晰权限要求、影响说明和有效还原路径；每项遗留问题都能定位到具体功能与证据。
